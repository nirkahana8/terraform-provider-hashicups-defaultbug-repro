# An object plan modifier on a CustomType `SingleNestedAttribute` crashes with "Attribute Missing" when the attribute is unknown in the plan on create

### Module version

```
github.com/hashicorp/terraform-plugin-framework v1.19.0
github.com/hashicorp/terraform-plugin-go        v0.31.0
Terraform                                        v1.5.7
```

### Relevant provider source code

Schema generated by `tfplugingen-framework generate all` (so `nested` is backed by
the strict generated CustomType `NestedType`):

```go
func ThingResourceSchema(ctx context.Context) schema.Schema {
	return schema.Schema{
		Attributes: map[string]schema.Attribute{
			"id": schema.StringAttribute{
				Computed: true,
			},
			"nested": schema.SingleNestedAttribute{
				Attributes: map[string]schema.Attribute{
					"child": schema.StringAttribute{
						Optional: true,
						Computed: true,
					},
				},
				CustomType: NestedType{
					ObjectType: types.ObjectType{
						AttrTypes: NestedValue{}.AttributeTypes(ctx),
					},
				},
				Optional: true,
				Computed: true,
			},
		},
	}
}
```

The resource `Schema()` attaches the stock object plan modifier to `nested`:

```go
s := gen.ThingResourceSchema(ctx)
nested := s.Attributes["nested"].(schema.SingleNestedAttribute)
nested.PlanModifiers = append(nested.PlanModifiers, objectplanmodifier.UseStateForUnknown())
s.Attributes["nested"] = nested
resp.Schema = s
```

Config omits `nested`:

```hcl
resource "usfu_thing" "test" {}
```

### Expected behavior

`nested` is unknown in the plan; `UseStateForUnknown` is a no-op on create (no prior
state). Plan should succeed with `nested = (known after apply)`.

### Actual behavior

`terraform plan` fails:

```
Error: Attribute Missing
child is missing from object
```

### Conditions

The crash requires **all** of:

1. a generated CustomType `SingleNestedAttribute`,
2. an **object plan modifier** attached to it (here `objectplanmodifier.UseStateForUnknown()`), and
3. the attribute is **unknown in the plan with no prior state to substitute** — i.e. **create** with the attribute omitted (Optional+Computed).

It does **not** crash when:

- the attribute is present in config (known in the plan),
- on update (prior state substitutes via `UseStateForUnknown`), or
- the modifier is not attached (removing it yields a clean `nested = (known after apply)`).

The **child type is irrelevant** — a scalar child (`child` string, above) crashes
just the same as a nested-object child.

`objectplanmodifier.UseNonNullStateForUnknown()` fails **identically** (same
`child is missing from object` on create-omitted), which confirms the crash is
triggered by attaching *any* object plan modifier — not by the specific modifier's
logic (both no-op on create, since there is no prior state).
