# An object plan modifier on a CustomType `SingleNestedAttribute` crashes with "Attribute Missing" when the attribute is unknown in the plan on create

### Module version

```
github.com/hashicorp/terraform-plugin-framework v1.19.0
github.com/hashicorp/terraform-plugin-go        v0.31.0
Terraform                                        v1.5.7
```

### Relevant provider source code

Schema generated by `tfplugingen-framework generate all` (so `engine` is backed by
the strict generated CustomType `EngineType`):

```go
func CarResourceSchema(ctx context.Context) schema.Schema {
	return schema.Schema{
		Attributes: map[string]schema.Attribute{
			"id": schema.StringAttribute{
				Computed: true,
			},
			"name": schema.StringAttribute{
				Required: true,
			},
			"color": schema.StringAttribute{
				Optional: true,
				Computed: true,
			},
			"engine": schema.SingleNestedAttribute{
				Attributes: map[string]schema.Attribute{
					"kind": schema.StringAttribute{
						Optional: true,
						Computed: true,
					},
					"volume": schema.Int64Attribute{
						Optional: true,
						Computed: true,
					},
				},
				CustomType: EngineType{
					ObjectType: types.ObjectType{
						AttrTypes: EngineValue{}.AttributeTypes(ctx),
					},
				},
				Optional: true,
				Computed: true,
			},
		},
	}
}
```

The resource `Schema()` attaches the stock object plan modifier to `engine`:

```go
s := gen.CarResourceSchema(ctx)
engine := s.Attributes["engine"].(schema.SingleNestedAttribute)
engine.PlanModifiers = append(engine.PlanModifiers, objectplanmodifier.UseStateForUnknown())
s.Attributes["engine"] = engine
resp.Schema = s
```

Config omits `engine`:

```hcl
resource "usfu_car" "audi" {
  name  = "A8"
  color = "white"
}
```

### Expected behavior

`engine` is unknown in the plan; `UseStateForUnknown` is a no-op on create (no prior
state). Plan should succeed with `engine = (known after apply)`.

### Actual behavior

`terraform plan` fails:

```
Error: Attribute Missing
kind is missing from object
```

### Conditions

The crash requires **all** of:

1. a generated CustomType `SingleNestedAttribute`,
2. an **object plan modifier** attached to it (here `objectplanmodifier.UseStateForUnknown()`), and
3. the attribute is **unknown in the plan with no prior state to substitute** — i.e. **create** with the attribute omitted (Optional+Computed).

It does **not** crash when:

- the attribute is present in config (known in the plan),
- on update (prior state substitutes via `UseStateForUnknown`), or
- the modifier is not attached (removing it yields a clean `nested = (known after apply)`).

The **child attributes are irrelevant** — scalar children (`kind` string, `volume` int64) crash
just the same as if the nested object had object-typed children.

`objectplanmodifier.UseNonNullStateForUnknown()` fails **identically** (same
`child is missing from object` on create-omitted), which confirms the crash is
triggered by attaching *any* object plan modifier — not by the specific modifier's
logic (both no-op on create, since there is no prior state).
